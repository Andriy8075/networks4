# Інструкція: лабораторна робота №4

**Тема.** Аналіз мережевого трафіку. Дослідження DNS, TCP та HTTP у контейнерній мережі та діагностика несправностей вебпроксі.

**Мета.** Захопити трафік контейнеризованого застосунку ЛР1 і проаналізувати його в Wireshark: DNS, TCP handshake, HTTP, обмін з Redis; додатково відтворити помилковий порт Nginx (502) і відновлення.

**Стенд.** Готовий проєкт [`lab1/code`](../lab1/code): сервіси `proxy` (nginx, хост **8080**), `app` (Flask на **8000**, 2 репліки), `db` (Redis **6379**). Новий Compose для ЛР4 **не** потрібен.

**Середовище.** Команди Docker / `nsenter` / `tcpdump` / `dig` — у **WSL Ubuntu**. Аналіз PCAP — у **Wireshark на Windows**. Артефакти — у [`evidence/`](evidence/).

**Максимальний бал.** Виконайте основне (п. 1–8) **і** додаткове (помилковий порт → `failure.pcap` → відновлення → `recovered.pcap`).

### Пункт 8. Команда Redis

1. Відкрийте `database.pcap`.
2. Фільтр: `tcp.port == 6379` (або `resp`, якщо Wireshark розпізнав RESP).
3. ПКМ по пакету → **Follow → TCP Stream**.
4. У потоці має бути команда на кшталт `*2\r\n$4\r\nINCR\r\n$7\r\ncounter\r\n` і відповідь цілим числом (`:N`).

**Зіставлення з HTTP.** Тіло відповіді Flask містить `Visit count: N` — це те саме значення після `INCR`.

**Код обробника** (коротко для звіту):

```python
visits = r.incr('counter')
return f"Hello from Flask App! Visit count: {visits}\n"
```

**Скрін.** `10-redis-stream.png`.

### Д.4. Аналіз `failure.pcap`

### Д.5. Порівняння портів і причина

| Джерело | Порт |
|---------|------|
| Захоплення (destination SYN) | `8080` |
| Журнал Nginx | згадка upstream / `app:8080` |
| Фактичний listen застосунку | `8000` (`EXPOSE` / `app.run(..., port=8000)`) |
| Помилковий рядок конфігу | `proxy_pass http://app:8080;` |

**Пояснення.** Клієнт успішно з’єднується з nginx на опублікованому 8080→80. Проксі намагається прокинути запит на правильне ім’я `app`, але на **неправильний порт 8080**, де ніхто не слухає → RST → nginx віддає клієнту 502. Сам код 502 лише наслідок, причина — wrong upstream port.

## Аналіз у Wireshark (шпаргалка фільтрів)

| Фільтр | Що шукати |
|--------|-----------|
| `dns` | запит/відповідь, Transaction ID |
| `tcp.flags.syn == 1` | SYN і SYN/ACK |
| `tcp.stream eq N` | один TCP-потік |
| `http.request` / `http.response` | метод, URI, код |
| `tcp.port == 6379` | Redis |
| `resp` | розбір RESP (якщо доступний) |
| `tcp.flags.reset == 1` | RST при wrong port |
| `http.response.code == 502` | відповідь клієнту при збої |

ПКМ по пакету → **Follow → TCP Stream** для HTTP і Redis.
